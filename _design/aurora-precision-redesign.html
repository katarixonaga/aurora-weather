Product & visual design · direction: precision dashboard

A meteo console that stays calm while carrying everything.

Aurora already runs a serious data engine — 10-year ERA5 climatology, CAPE/CIN/shear storm logic, radar, air quality, warming stripes — all client-side. This redesign keeps every byte of that engine and rebuilds the surface as a rigorous instrument: one clear grid, tabular data-ink, custom gauges and sparklines, and progressive disclosure so a dense app reads at a glance. Elegant restraint over spectacle, and it finally earns its name with a real aurora / Kp forecast from NOAA SWPC.

0 new dependencies 2 CDN libs kept · Chart.js + Leaflet +1 origin to CSP · SWPC EN · DE · °C · °F · dark · light preserved reduced-motion first-class
01

Layout & information architecture

structure

The current app is a single long scroll of full-width cards — correct, but it reads as a feed, not an instrument. The redesign keeps one scroll but imposes a 12-column console grid (max-width: 1240px, up from 1080) with a clear altitude: a fixed summary that answers "what do I need to know right now," then progressively denser detail below. Nothing is removed; things are re-ranked and de-emphasized until asked for.

03

Typography

no paid fonts

The current app loads Inter from Google Fonts. The console keeps a clean grotesque for prose but adds the move that makes it read as an instrument: a monospace for every number, label and unit — tabular, engineering, unmistakably "data." Both are free. To stay bulletproof under the strict CSP, the safest path is a system stack (zero network, zero CSP risk, zero FOUT). If Inter is kept, it is already whitelisted in style-src/font-src — but the mono role must be added.

04

Motion & animation

transform + opacity only

The current app animates card entry, icon float/spin, rain drops and lightning flash. The console keeps motion diegetic and cheap — it should feel like an instrument settling, not a splash screen. Everything below is GPU-friendly (transform/opacity only, no layout-triggering props), tuned for a modest laptop, and fully switched off under prefers-reduced-motion.

Extends the block already in styles.css. The ambient wash still changes color on condition change — it just does so instantly, so information is never lost.

Hero treatment

◆ signature

The hero stops being "a big temperature and a sentence" and becomes the glance instrument: the one giant number, condition, feels-like, and a built-in 4-cell glance strip + 24-hour temperature sparkline — everything you'd want before deciding whether to read further. A quiet ambient sky wash sits behind it so it still feels like weather, but the data stays on neutral panel ink.

  • Right: condition, feels-like, H/L, and a live anomaly readout ("+3° vs normal") pulled straight from the existing analyze() output — surfacing the app's best hidden insight into the fold.

Responsive behavior

mobile → desktop
Mobile ≤560
  • Single column, full-bleed panels, 16px gutters.
  • Hero temp 64px; glance strip 2×2.
  • Command bar: brand + search collapse; actions become an overflow menu behind one button.
  • 14-day track hides the anomaly column; kept on expand.
  • Chart height 160px; hour rail scrolls (kept).
  • Sticky bar shrinks to 52px.
Tablet 561–1024
  • Hero full width; Sky-tonight drops below hero, full width.
  • Now-detail tiles 3–4 up (auto-fit).
  • Climate band stacks chart over records.
  • Map 380px.
  • Two-up where minmax(220px,1fr) allows.
Desktop ≥1080
  • Full 12-col grid, max-width 1240px.
  • Hero 7 cols · Sky-tonight 5 cols, side by side.
  • Now-detail 4-up; climate 2-up.
  • Everything above the map visible in ~1.5 screens.
  • Hover affordances (scrub, tooltips) enabled.
Technique All grids are grid-template-columns: repeat(auto-fit, minmax(…,1fr)) with minmax(0,1fr) guards so nothing overflows; wide content (chart, map, 14-day track, spec tables) each get their own overflow-x:auto container so the page body never scrolls sideways. Breakpoints extend the existing single @media(max-width:560px) block to a small set: 560 · 880 · 1080.

Signature moments

◆ unique to this direction

Three things a generic weather app won't have — each grounded in a confirmed free, no-key data source and in the app's own identity.

AAurora tonight — the app finally earns its nameNOAA SWPC
A live Kp gauge and tonight's aurora probability for your exact lat/lon — from the planetary-K feed and the OVATION aurora grid (nearest cell lookup). Plus the 3-day geomagnetic outlook as a mono mini-forecast.
Aurora possible Prob 38% · nearest cell Best 22:00–01:00

Adds services.swpc.noaa.gov to connect-src. Cached 15 min. Pairs with locally-computed moon phase + golden/blue hour in the same "Sky tonight" panel — no API needed for those.

BThe one-screen glance — hero as instrumentno new data
Everything that matters — now temp, condition, feels-like, live anomaly vs local normal, the four go/no-go metrics, and a 24h sparkline — resolves in a single fold with zero interaction. It reuses data the app already fetches, so it costs nothing but re-composition. The "+3° vs normal" readout, currently buried in the history section, becomes the app's headline insight where people actually look. This is the calm-yet-dense thesis of the whole direction.
CScrubbable warming stripes + climate scrub-lineERA5, already loaded
The 40-year warming stripes gain a hover/drag scrubber: move across the years and a mono tooltip reads out that year's mean and its delta from the 1980s baseline, with a thin vertical marker — turning a static gradient into an explorable 40-year record. On the forecast-vs-normal chart, a shared vertical scrub-line links hovering any day to its anomaly and percentile from analyze(). Both are pure client-side reads of data already in memory. A quietly beautiful, genuinely informative interaction that no mass-market weather app offers.

Build notes & CSP

stays static
  • No framework, no build step, no backend — remains vanilla HTML/CSS/JS on GitHub Pages. The redesign is CSS-token + render-function work over the existing engine; JS data functions (getForecast, buildClim, analyze, buildAlerts, scanArea) are untouched.
  • Libraries unchanged: Chart.js 4.4.1 + Leaflet 1.9.4, same CDN + SRI. New charts (sparklines, gauges) are hand-rolled inline SVG — no new library.
  • One CSP change: add https://services.swpc.noaa.gov to connect-src for the aurora feature. Everything else (Open-Meteo extended fields: uv_index, dew_point_2m, visibility, cloud_cover_low/mid/high, pressure tendency, sunrise/sunset) uses origins already whitelisted.
  • Fonts: if going system-only, drop the Google Fonts <link> and its style-src/font-src entries → fewer origins, zero FOUT. If keeping Inter, no CSP change; just add the system mono stack (no network).
  • Perf on a modest laptop: glassy backdrop-filter: blur(20px) across every card is the current cost center — the console replaces it with flat panels + hairlines and keeps blur only on the sticky bar. Sparklines/gauges are static SVG. Net: fewer composited layers, smoother scroll.
  • i18n: every new string (Sky-tonight, aurora states, tile labels, gauge captions) added to the EN/DE dictionaries in i18n.js following the existing tr(key,params) pattern — full parity maintained.
